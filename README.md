# OpenTubeRecommendations — локальный анонимный рекомендатель YouTube

Лента из ваших каналов вместо рекомендаций YouTube: без шортсов, без аккаунта, без телеметрии.
Ранжирование учится на ваших 👍/👎. Всё хранится и считается на вашей машине (папка `data/`).

* Сервер слушает только `127.0.0.1`. Сеть — только youtube.com / ytimg.com (и скачивание моделей по кнопке).
* Работает **без единой нейросети** (режим «Лёгкий»: правила, веса каналов, TF-IDF + логрегрессия).
  Нейросети (эмбеддинги, LLM, vision, Whisper) — по желанию, выбираете и скачиваете сами.
* Профили («Отдых», «Образование», …) с раздельными оценками, правилами и каналами.
* Лицензия проекта — MIT, все зависимости — под OSI-лицензиями (см. `THIRD_PARTY_LICENSES`).

## Быстрый старт

Нужен Linux, git и один из двух: Nix или uv. Нейросети, видеокарта и аккаунты не нужны.

Скачайте проект командой git clone https://github.com/seregabitvibecoder2026/OpenTubeRecommendations.git, зайдите в папку и выполните ./start

Приложение откроется в браузере на http://127.0.0.1:8765, дальше его проведёт мастер первого запуска.

Если после добавления каналов лента пустая: откройте «Правила и вкус», поднимите «Не старше, дней» (по умолчанию 365, более старые видео скрыты), затем «Задачи» → «Обновить ленту».


## Установка и запуск

Нужен только Linux (проверено на NixOS), `git` и **один** из вариантов: Nix или `uv`.
Нейросети, видеокарта и аккаунты не нужны.

### NixOS / Linux с Nix

```bash
git clone https://github.com/seregabitvibecoder2026/OpenTubeRecommendations.git
cd OpenTubeRecommendations
./start
```

`./start` сам заходит в dev-shell из `./nix` (python 3.12, uv, yt-dlp, ffmpeg, deno), ставит зависимости
по `uv.lock` в `.venv` и открывает браузер на <http://127.0.0.1:8765>. Флаги flakes включать в системе не
нужно — они передаются в команде. Первый запуск качает зависимости (~150 МБ), дальше приложение
стартует и без интернета.

### Любой другой Linux (без Nix)

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # если uv ещё нет (или пакетом дистрибутива)
git clone https://github.com/seregabitvibecoder2026/OpenTubeRecommendations.git
cd OpenTubeRecommendations
./start
```

Без Nix `./start` вызывает `./start.sh` (нужен только `uv`; Python 3.12 uv скачает сам).
Чтобы не использовать Nix, даже если он установлен: `YNG_NO_NIX=1 ./start`.

### Из архива

Вместо `git clone` можно распаковать `OpenTubeRecommendations-<версия>.tar.gz` (собирается `./make-release`)
и выполнить `./start` в папке.

### Обновление

```bash
git pull && ./start
```

Данные лежат в `data/` (вне git), обновление их не трогает.

Параметры: `YNG_PORT=8765` (порт), `YNG_DATA=/путь/к/data` (папка данных), `./start --no-browser`.

## Первый запуск

1. Мастер предложит режим: **Лёгкий** (без моделей), **Средний** (маленькая эмбеддинг-модель),
   **Полный** (эмбеддинги + LLM, по желанию vision). Всё меняется позже на странице «Модели».
2. Выберите шаблон первого профиля: «Отдых», «Образование» или «Пустой».
3. «Каналы» → вставьте ссылки/@хэндлы/ссылки на видео (или импорт `subscriptions.csv` из Google Takeout).
4. «Обновить ленту». Дальше — 👍/👎 на карточках: после ~30 оценок вкус работает в полную силу,
   после ~120 включается логистическая регрессия (пороги — в «Правилах»).

Ничего тяжёлого не запускается само: каждая операция — кнопка на странице «Задачи» с прогрессом,
логом и «Стоп». Автообновление есть, но выключено (Настройки → «Автообновление, часов»).

## Нейросети (необязательно)

Страница **«Модели»**: каталог эмбеддингов, LLM, vision и ASR с размером на диске, нужной VRAM
по квантизациям, языками, **лицензией** и пометкой «влезет в мою карточку» (свободная VRAM
определяется через `nvidia-smi`). По умолчанию подсвечивается то, что укладывается в бюджет 4–6 ГБ VRAM,
и показываются только модели с открытыми лицензиями (Apache-2.0, MIT…); модели с «community»/custom/NC
лицензиями — за галочкой «показать и с ограниченной лицензией». Можно добавить свою модель (HF ID,
тег Ollama, GGUF-репозиторий). Кнопка «Тест» проверяет модель на вашей карточке и показывает занятую VRAM.

* **Эмбеддинги (sentence-transformers)**: «Модели» → «Python-пакеты» → «Установить» (ставит PyTorch с CUDA,
  ~2–3 ГБ, один раз), перезапустить `./start`, затем «Скачать» модель (например `multilingual-e5-small`),
  «Использовать», «Задачи» → «Посчитать эмбеддинги». Без GPU работает на CPU (медленнее).
  Альтернатива без PyTorch — эмбеддинг-модели через Ollama (`bge-m3`, `qwen3-embedding`).
* **LLM через Ollama** (по умолчанию): установите Ollama (на NixOS: `services.ollama.enable = true;`
  и `services.ollama.acceleration = "cuda";`, или пакет `ollama-cuda`), запустите `ollama serve`,
  затем в каталоге «Скачать» (= `ollama pull`) и «Использовать». Свои вопросы к модели — на странице
  «Правила и вкус» → «LLM-вопросы», запуск — «Задачи» → «Запустить LLM-анализ» (только для верхушки ленты).
* **llama.cpp / GGUF**: в каталоге GGUF-репозитория «Показать файлы» → выбрать квантизацию → скачать;
  движок «llama.cpp» запустит `llama-server` (должен быть в PATH). Или любой локальный OpenAI-совместимый
  сервер (LM Studio, vLLM) — движок «OpenAI-совместимый». Облачные адреса запрещены: только 127.0.0.1/LAN.
* **Vision** (анализ превью) — мультимодальные модели через Ollama (Qwen3-VL, moondream, …).
* **Whisper** (если у видео нет субтитров) — «Установить» движок ASR, скачать модель, включить
  источник `whisper` в Настройках → Источники → Субтитры.

## Как это работает

**Ранжирование** (всё в рамках активного профиля; веса — слайдеры на странице «Правила и вкус»):
вкус (близость к центру лайков минус к центру дизлайков: эмбеддинги или TF-IDF; при ≥120 оценках —
логрегрессия), канал (ваш вес канала + средняя оценка его видео), правила (темы, стоп-темы, плотность мата
по субтитрам/комментариям), свежесть (экспоненциальное затухание), LLM-оценки, язык. У каждой карточки
есть «почему тут» с вкладом факторов. Доля ленты (по умолчанию 15%) — «исследование»: видео вне профиля.

**18+ и неполные данные.** Без входа YouTube отдаёт для age-restricted видео не всё. Для каждого видео
хранится, какие данные реально получены (`evidence`) и полнота (`confidence`). Отсутствующие данные не
считаются нулями: берётся приор канала (среднее по его видео) или фактор выпадает с перенормировкой
весов. Слайдер «доверие к неполным данным» подтягивает такие оценки к среднему по каналу.
Лайки на 18+ весят столько же, сколько на остальных. Это покрыто тестами.

**Что реально работает без логина** (проверено на момент разработки, 2026-11; YouTube меняется —
нажмите «Задачи» → «Проверить доступные источники для 18+» или «🔬» на странице видео):

| Источник | Обычные видео | 18+ |
|---|---|---|
| RSS (`feeds/videos.xml`, плейлист `UULF…`) | **отдавал 404/500** — используется резерв | — |
| Вкладка `/videos` через yt-dlp (только длинные ролики) | ✅ (даты приблизительные) | ✅ в списке |
| Публичная страница видео (название, описание, теги, дата, длительность, флаг 18+) | ✅ | ✅ |
| yt-dlp: полные метаданные, субтитры, комментарии | ✅ | ❌ все `player_client` (default, tv_embedded, web_embedded, tv, mweb) требуют вход |
| Комментарии со страницы видео | ✅ | ❌ |
| Эскиз (`i.ytimg.com`) | ✅ | ✅ |

Порядок и включение источников настраиваются (Настройки → Источники). Есть необязательные:
свой ключ YouTube Data API, Invidious/Piped-инстанс (адрес вписываете сами), куки своего браузера
для yt-dlp (выключено; нарушает ToS и связывает запросы с вашим аккаунтом).

**Шортсы** отсекаются трижды: плейлист `UULF…`/вкладка `/videos` (там нет шортсов), ссылки `/shorts/`,
порог длительности (по умолчанию 3 мин, настраивается в профиле).

**Языки.** Язык видео — из метаданных yt-dlp, иначе детектор по названию/описанию/субтитрам.
Словари мата, стоп-слова и темы — по языкам (ru, en, можно добавить любой), фильтр и вес языка в ленте.
TF-IDF строится на символьных n-граммах — одинаково для русского (морфология) и английского.

## Приватность

* Нет аккаунтов, логина, телеметрии. Сервер — только `127.0.0.1`.
* Все HTTP-запросы приложения идут через один клиент с белым списком хостов (`app/net.py`):
  youtube.com/ytimg.com; Data API — только если вы вписали ключ; Invidious/Piped — только ваш адрес;
  LLM/эмбеддинги — только локальные адреса. Превью картинок тоже идут через приложение (с кэшем и прокси),
  браузер к YouTube не обращается. Модели скачиваются только по кнопке (huggingface.co или Ollama).
* Единственная куки — `SOCS=CAI`: ответ «отклонить всё» на баннер согласия YouTube в ЕС (как делает
  yt-dlp), без идентификаторов. Без неё страницы каналов редиректят на consent.youtube.com.
* Прокси (HTTP/SOCKS, Tor `socks5://127.0.0.1:9050`) — в Настройках, применяется и к yt-dlp.
* Вежливость: пауза между запросами, лимит параллелизма, повторы с backoff, кэш.

## Профили

Профиль — локальный раздел данных (UUID), не аккаунт: свои оценки, вкус, веса, словари, LLM-вопросы,
каналы и их веса. Кэш видео, модели и сетевые настройки — общие. Переключатель — в шапке каждой страницы.
Экспорт/импорт профиля одним JSON-файлом; по умолчанию **без** истории оценок (можно передать пресет
друзьям), история — отдельной галочкой. При импорте — «как новый» или «заменить» (тот же UUID).

## Разработка

```bash
nix --extra-experimental-features 'nix-command flakes' develop ./nix   # или просто uv
uv sync --group dev
.venv/bin/python -m pytest -q                  # тесты (без сети, без моделей)
.venv/bin/python scripts/check_licenses.py     # падает, если нашлась не-OSI лицензия (--write обновит THIRD_PARTY_LICENSES)
./make-release                                 # dist/OpenTubeRecommendations-<версия>.tar.gz без data/, моделей и ключей
```

Структура:

```
app/
  main.py          FastAPI + страницы (Jinja2 + HTMX, без сборки фронтенда)
  ranking.py       ранжирование, вкус, приоры, исследование
  collect.py       цепочки провайдеров: список видео, метаданные, субтитры, комментарии, проба источников
  providers/       весь неофициальный парсинг (rss, ytdlp, watchpage, ytapi, altfront) — чинить здесь
  tasks.py jobs.py задачи с прогрессом и «Стоп»
  ml/              каталог моделей, движки (sentence-transformers, Ollama, OpenAI-совместимый, llama.cpp, Whisper)
  net.py           единственный HTTP-клиент, белый список хостов
  text.py          язык, мат, правила, фильтр комментариев
  profiles.py db.py config.py i18n.py (строки интерфейса)
nix/               dev-shell (flake), используется ./start; flake.nix в корне — то же для `nix develop`
```

Почему dev-shell лежит в `./nix`: flake из корня проекта заставил бы Nix копировать в store всю папку,
включая `.venv` и `data/` с моделями.
