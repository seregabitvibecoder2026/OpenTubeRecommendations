# ТЗ: локальный анонимный рекомендатель YouTube («свой фид»)

Для Claude Code. Прочитай целиком, потом предложи структуру проекта и начинай с этапа 1. Не усложняй: сначала рабочий минимум, потом наращивание. Всё должно управляться руками через интерфейс.

## 1. Цель
Приложение, которое строит ленту из ютуб-каналов пользователя вместо родных рекомендаций ютуба (там шортсы, "соевый" контент, нет мата). Ранжирование обучается на личных оценках пользователя. Всё работает локально, без аккаунтов, без телеметрии.

Вкусовые ориентиры пользователя (должны настраиваться, не зашиваться в код): без шортсов, без "повесточки", с юмором, мат — плюс.

## 2. Жёсткие требования
- **Анонимность**: никаких аккаунтов Google, куки, логинов. Никакой телеметрии и внешних сервисов, кроме запросов к youtube.com. Сервер слушает только 127.0.0.1. Опциональный прокси (HTTP/SOCKS, Tor) в настройках.
- **Локально**: данные, модели, нейросети — на машине пользователя. База — SQLite в одной папке `data/`.
- **Портативно**: проект раздаётся друзьям архивом (zip/tar). Железо у них такое же: Linux/NixOS, NVIDIA RTX 5060 Ti 8 ГБ VRAM, 32 ГБ RAM, Ryzen/Intel 7700, медленная DDR4. В архив НЕ входят `data/`, модели и ключи. Моделей по умолчанию нет вообще: пользователь сам выбирает и скачивает их (или остаётся в режиме "Лёгкий").
- **Ручное управление**: ничего тяжёлого не запускается само. Каждый этап — отдельная кнопка с прогрессом и кнопкой "Стоп". Всё конфигурируется из UI.
- **Простота запуска**: одна команда/ярлык (`./start`), открывает браузер на localhost.
- **Всё open source**: проект под свободной лицензией (по умолчанию MIT или GPL-3.0, выбрать на старте и положить `LICENSE`). Все зависимости — только под OSI-одобренными лицензиями, файл `THIRD_PARTY_LICENSES`. Никаких проприетарных библиотек и облачных нейросетевых API в коде (только локальные модели). Модели в каталоге помечать лицензией; по умолчанию показывать и рекомендовать модели с открытыми лицензиями (Apache-2.0, MIT и т.п.), а модели с ограничительными "community"/custom-лицензиями — скрывать за фильтром "показать и с ограниченной лицензией". Единственный необязательный нечистый элемент — собственный ключ YouTube Data API (внешний сервис, по умолчанию выключен).

## 3. Стек
- Python 3.12, менеджер `uv`. FastAPI + SQLite (sqlite3 или SQLAlchemy).
- Фронтенд без сборки: HTMX + немного vanilla JS + простой CSS (никакого node/npm для пользователя).
- Сбор данных: `yt-dlp` (метаданные, субтитры), RSS-ленты YouTube, `httpx`.
- **Нейросети НЕ входят в проект и не выбираются за пользователя.** Менеджер моделей (см. п. 3.1) показывает варианты, пользователь сам решает, что скачать.
- Эмбеддинги (опционально): `sentence-transformers`, CUDA с откатом на CPU. Каталог в менеджере (примеры, актуализировать при реализации): `multilingual-e5-small/base/large`, `bge-m3`, `Qwen3-Embedding` (0.6B и выше), `jina-embeddings-v3` (если лицензия подходит), либо любой свой HuggingFace ID. Должны быть многоязычными (русский + английский).
- LLM (опционально): локальный движок на выбор пользователя — Ollama (по умолчанию) или `llama.cpp`/llama-server с GGUF-файлом, либо любой OpenAI-совместимый локальный эндпоинт (LM Studio-подобные, vLLM). Каталог пресетов с широким выбором (примеры): семейства Qwen3 (4B/8B/14B…), Gemma 3 (4B/12B…), Mistral/Ministral, Phi-4-mini, Llama 3.x, GLM, DeepSeek-дистилляты и т.д.; плюс поле "свой тег/свой GGUF". Пользователь выбирает сам.
- Vision-модели (опционально): локальные мультимодальные модели (Qwen-VL, Gemma 3 с vision, moondream, SmolVLM и т.п.) для анализа превью-картинок (см. п. 4.2).
- ASR (опционально, запасной вариант без субтитров): `faster-whisper`, любой размер от tiny до large-v3-turbo (мультиязычный).
- **Бюджет по умолчанию 4–6 ГБ — это ВИДЕОПАМЯТЬ (VRAM)**, под карточку 8 ГБ (с запасом под систему). Физический размер файлов на диске не ограничивается, это выбор пользователя.

### 3.1 Менеджер моделей и первый запуск
- Приложение полностью работает **без единой нейросети** (режим "Лёгкий"): ранжирование по правилам, весам каналов и классическому ML на TF-IDF (scikit-learn) по названиям и описаниям. Ноль скачиваний, архив остаётся маленьким.
- Мастер первого запуска предлагает режимы: **Лёгкий** (без моделей), **Средний** (маленькая эмбеддинг-модель), **Полный** (эмбеддинги + LLM на выбор пользователя, опционально vision). Всё пропускается и меняется позже.
- В менеджере: широкий каталог моделей (эмбеддинги, LLM, vision, ASR) с колонками: размер на диске, нужная VRAM (по квантизациям), языки, **лицензия**, пометка "влезает в мою карточку" (определять свободную VRAM автоматически). Кнопки "Скачать" (явный показ размера) и "Удалить", ввод своего HF ID / тега / пути к GGUF, тест "работает ли на моей карточке". Скачивание только по нажатию.
- Фильтры каталога: по VRAM-бюджету (по умолчанию подсвечивать то, что укладывается в 4–6 ГБ VRAM), по типу, по лицензии (см. п. 2 об open source). Пользователь может превысить бюджет вручную (с предупреждением, возможен частичный оффлоад на CPU/RAM).
- Дистрибуция: `flake.nix` (devShell: python, uv, yt-dlp, ffmpeg; CUDA-пакеты) + запасной скрипт `start.sh` на `uv` для не-Nix систем. Lock-файл в репозитории. README на русском, по шагам.

## 4. Сбор данных (без аккаунта, без обязательного API-ключа)
- Список каналов хранится в БД. Добавление: вставка ссылок/@хэндлов/ссылки на видео, импорт `subscriptions.csv` из Google Takeout, массовая вставка текстом. Хэндл → channel_id резолвится парсингом страницы канала или через yt-dlp.
- Свежие видео: RSS `https://www.youtube.com/feeds/videos.xml?channel_id=UC...`.
- **Фильтр шортсов**: RSS плейлиста `playlist_id=UULF<часть ID канала после UC>` отдаёт только длинные видео (не шортсы). Резерв: порог длительности (настраиваемый, по умолчанию 3 мин).
- Метаданные (длительность, просмотры, теги, описание): `yt-dlp` без логина. Опционально YouTube Data API v3 — пользователь может вписать свой ключ в настройках (квота 10 000 единиц/сутки; `playlistItems`/`videos.list` по 1 единице, `search.list` 100 — использовать редко). Абстрагировать как провайдеры данных, чтобы приложение работало и без ключа.
- **18+ видео** (`age_restricted`): они должны оцениваться пользователем и нейросетью **наравне с остальными** (см. п. 4.2 и п. 6). Вход в аккаунт не требуется.
- Субтитры: `yt-dlp --write-auto-subs --skip-download`, хранить только текст. Если нет — опциональный Whisper.
- Вежливость к ютубу: настраиваемая пауза между запросами, ретраи с backoff, лимит параллелизма, кэш (не запрашивать повторно).

## 4.2 Равноправная оценка 18+ видео и комментарии
Проблема: без входа в аккаунт ютуб может не отдавать субтитры, аудио и комментарии age-restricted видео. Цель: всё равно собрать максимум сигналов и честно оценивать. **Не обещать заранее, что что-то работает: каждый источник проверять эмпирически и логировать результат.**

Цепочка источников (провайдеры, каждый можно включать/выключать в настройках, порядок настраивается; идём по цепочке до первого успеха по каждому типу данных):
1. **Метаданные из RSS/API/yt-dlp**: название, описание, теги, главы, канал, длительность, дата (доступны почти всегда).
2. **Комментарии** (`yt-dlp --write-comments`, ограничение через extractor-args, по умолчанию топ 50–100 по популярности, настраивается): текст комментариев — дополнительное поле, которое идёт в эмбеддинги и LLM ("о чём видео, какой тон, что обсуждают, юмор ли"). Нужно для **всех** видео, не только 18+, но для 18+ особенно важно. Фильтровать спам/боты/таймкоды-однострочники, ограничивать длину. Загружаются отдельной кнопкой (задача), с паузами.
3. **Попытки получить субтитры/комментарии age-restricted без логина**: перебор клиентов yt-dlp (`player_client`, включая embed/TV-варианты — они иногда отдают такие видео для встраиваемых роликов); опциональный провайдер через **открытые альтернативные фронтенды** (Invidious/Piped-инстансы с адресом, который вписывает пользователь; по умолчанию выключен, с предупреждением о приватности и нестабильности). Всё изолировано в провайдерах, чтобы чинить в одном месте. Реализовать пробный режим "проверить, что доступно для этого видео" и показать результат в UI.
4. **Эскизы (thumbnails)** — публичны без логина: опциональный анализ vision-моделью (что изображено, тон, стиль) как ещё один текстовый признак.
5. **Профиль канала как приор**: оценка и тональность видео наследуются от остальных видео и лайков по этому каналу (особенно если его обычные ролики доступны полностью). Это главный страхующий сигнал для закрытых видео.
6. Опционально и выключено по умолчанию: куки собственного браузера (`--cookies-from-browser`) с предупреждением о нарушении ToS и рисках; ровно для тех, кто сам захочет.

Равноправие при ранжировании и оценке:
- Лайки/дизлайки на 18+ видео весят столько же, сколько на остальных, и обучают ту же модель вкуса.
- Для каждого видео хранить `evidence` — какие поля реально получены (метаданные / комментарии / субтитры / эскиз / приор канала) и `confidence` (0–1). Отсутствующие поля не считать нулями, а восполнять приором канала или пропускать с перенормировкой весов, чтобы 18+ видео не получали систематический штраф или бонус из-за дыр в данных.
- В карточке — значок "18+" и маркер полноты данных ("оценка по неполным данным"); в настройках — слайдер "доверие к неполным данным" и переключатель "показывать 18+ в ленте: да/нет/только они".
- LLM получает тот же шаблон вопросов и список доступных полей, с пометкой "поле X недоступно", чтобы не придумывать недостающее.

## 4.1 Языки (русский и английский)
- Пользователь смотрит контент и на русском, и на английском. Всё должно работать на обоих.
- Определение языка видео: из метаданных yt-dlp (`language`) с резервом на лёгкий детектор по названию/описанию/субтитрам (`lingua-py` или `langdetect`). Хранить в `videos.lang`.
- Словари мата, стоп-слова и стоп-темы — **по языкам** (ru, en, расширяемо), редактируются в UI.
- Эмбеддинг-модели только многоязычные; в режиме "Лёгкий" TF-IDF строится отдельно по каждому языку или на общем словаре (на усмотрение, но без деградации для английского).
- Предпочтительные языки субтитров — список в настройках (по умолчанию ru, en).
- Фильтр языка в ленте: "все / только ru / только en / выбранные". Вес языка в ранжировании — слайдер.
- LLM-вопросы формулируются на языке пользователя, но модель получает текст на любом из двух языков; в промпте указать "отвечай по схеме JSON независимо от языка источника".
- Интерфейс на русском, архитектура готова к локализации (строки в словаре, не в шаблонах).

## 5. Данные (SQLite)
`profiles`, `channels`, `profile_channels`, `videos` (id, channel_id, title, description, tags, lang, duration, published_at, views, age_restricted, subtitles_text, embedding BLOB), `feedback` (profile_id, video_id, kind: like/dislike/hide/opened, ts), `video_scores` (profile_id, video_id, llm_scores JSON, rank), `rules` (profile_id, ...), `settings` (глобальные), `jobs`. Миграции простые, версия схемы в БД.

## 5.1 Профили (режимы: образование, отдых и т.д.)
- Локальная сущность "профиль", **не аккаунт**: у каждого профиля свой уникальный идентификатор (UUID, генерируется при создании), имя, цвет/иконка. Никуда не отправляется, служит для разделения данных и для переноса пресетов.
- Профиль хранит **отдельно**: лайки/дизлайки/историю, вкусовую модель, веса, словари и стоп-темы, LLM-вопросы, процент исследования, фильтр языка, набор активных каналов и их веса, настройки ленты.
- Общие для всех профилей: кэш видео (метаданные, субтитры, эмбеддинги — не считать дважды), модели, сетевые настройки, пул каналов. Один канал может входить в несколько профилей с разным весом (например, лекции в "Образовании" и в "Отдыхе" с разным весом).
- UI: переключатель профиля в шапке на каждой странице (выпадающий список + быстрое переключение), кнопки "Создать", "Дублировать" (с копированием настроек, без истории — по выбору), "Переименовать", "Удалить", "Экспорт/импорт профиля" (JSON с UUID; при импорте предложить "как новый профиль" или "заменить").
- При смене профиля лента пересобирается из кэша мгновенно; тяжёлых вычислений без кнопки не запускается.
- Стартовые шаблоны при создании: "Отдых", "Образование", "Пустой" (пользователь может создавать любые).

## 6. Ранжирование
Итоговая оценка = комбинация (веса настраиваются слайдерами):
1. **Вкус** (всё считается в рамках активного профиля): если установлена эмбеддинг-модель — близость эмбеддинга к центру лайков минус близость к центру дизлайков; в режиме "Лёгкий" — то же самое на TF-IDF-векторах. Когда оценок мало (<30) — опора на правила и веса каналов. Когда накопится ~100–200 оценок — обучаемая модель (логистическая регрессия) на признаках.
2. **Правила пользователя**: вес канала (+/-), стоп-слова и стоп-темы, "плотность мата" в субтитрах (словарь, редактируется в UI), бонус/штраф за темы.
3. **Свежесть**: затухание по возрасту (настраиваемый период).
4. **LLM-оценки** (если включено): локальная модель оценивает текст по вопросам, которые пользователь пишет сам в UI (например, "есть ли политическая агитация", "юмористический ли тон"), возвращает JSON 0–10. Промпты редактируются. Применять только к верхушке списка после дешёвой фильтрации.
5. **Исследование (exploration)**: доля X% (по умолчанию 15) видео вне профиля, чтобы лента не замыкалась. Настраивается.
Показывать у каждой карточки "почему тут" (вклад факторов).

## 7. Поиск новых каналов (этап 3)
Кандидаты: раздел "Рекомендованные каналы" со страницы канала, поиск по темам из лайков (редко, дорого по квоте), по желанию подсказки LLM. Кандидаты ранжируются тем же способом по их последним видео; пользователь принимает/отклоняет одной кнопкой.

## 8. UI (страницы)
- **Шапка (на всех страницах)**: переключатель профиля, статус моделей, индикатор запущенных задач.
- **Лента**: сетка карточек (превью, название, канал, язык, длительность, дата, значки "18+" / "мат"), фильтр языка. Кнопки: 👍, 👎, "скрыть канал", "ещё такое". Клик → открыть видео на youtube.com в новой вкладке (логируется как `opened`).
- **Каналы**: добавить/удалить/пауза, вес канала, импорт CSV.
- **Правила и вкус**: слайдеры весов, стоп-слова, словарь мата, порог длительности, % исследования, затухание свежести, редактор LLM-вопросов.
- **Задачи (Jobs)**: кнопки "Обновить ленту", "Скачать субтитры", "Загрузить комментарии", "Проверить доступные источники для 18+", "Проанализировать эскизы (vision)", "Посчитать эмбеддинги", "Запустить LLM-анализ", "Пересчитать ранг", у каждой — прогресс, лог, "Стоп". Ничего не стартует само (опциональный автообновлятор в настройках, выключен по умолчанию).
- **Настройки**: прокси, паузы/параллелизм, API-ключ (опц.), путь к `data/`, тема, языки субтитров.
- **Модели**: менеджер моделей (п. 3.1) — выбор, скачивание, удаление, проверка.
- **Профили**: управление профилями (п. 5.1), экспорт/импорт профиля одним файлом (JSON), кнопка "Сбросить профиль"/"Сбросить всё". Экспорт по умолчанию НЕ включает историю оценок (только правила, веса, словари, список каналов), чтобы друзьям можно было передавать пресеты без личных данных; включение истории — явная галочка.

## 9. Этапы
1. Каналы + RSS + фильтр шортсов + SQLite + лента + 👍/👎 + кнопка "Обновить" + **профили** (создание, переключение, раздельные оценки) + определение языка + режим "Лёгкий" (TF-IDF, без нейросетей). Запуск `./start`, flake.nix, README.
2. Менеджер моделей + эмбеддинги (по желанию пользователя) + ранжирование по оценкам + страница правил/весов + страница Jobs с прогрессом и Stop.
3. Субтитры, метрика мата, LLM-анализ через Ollama, редактор вопросов.
4. Поиск новых каналов, экспорт/импорт пресетов, упаковка в архив (скрипт `make-release`, исключающий `data/`).

## 10. Критерии готовности каждого этапа
- Запускается на чистой машине по README за ≤5 команд.
- Каждая тяжёлая операция прерывается кнопкой, UI не виснет.
- Без интернета, без GPU и **без единой скачанной модели** приложение запускается и полностью работает в режиме "Лёгкий", корректно сообщая, что недоступно.
- Архив релиза не содержит весов моделей, `data/` и ключей; размер архива — единицы мегабайт.
- Скрипт проверки лицензий зависимостей (падает, если найдена не-OSI лицензия), `LICENSE` и `THIRD_PARTY_LICENSES` на месте.
- 18+ видео проходят весь пайплайн (оценка, лайки, ранжирование) наравне с остальными; тест на то, что отсутствие субтитров/комментариев не даёт систематического смещения оценки (приор канала / перенормировка).
- Профили изолированы: оценки и настройки одного профиля не влияют на ленту другого (покрыть тестом).
- Английские и русские видео обрабатываются одинаково корректно (тесты на детектор языка и словари мата обоих языков).
- Нет ни одного обращения в сеть, кроме youtube.com (и скачивания моделей по явной кнопке).
- Есть тесты на парсинг RSS, фильтр шортсов, ранжирование (на заглушках, без сети).
